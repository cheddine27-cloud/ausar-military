## 1) الهيكل العسكري المدعوم

```
قيادة عامة (SuperAdmin) → قائد مركز → قائد سرية → رقيب/عريف (مدوّن الأفواج)
   الأفواج: فوج 1، فوج 2، ... ← كل فوج: قائمة عسكريين بقائمة رقمية
```

## 2) نموذج الحضور النهائي

```
حصة: [صباحية 🌅 | مسائية 🌙 | تمرين 🎯 | مراقبة 📋]
فوج 1 (30 عسكري):
  ✅ 27 حاضر
  ❌ 3 غياب:  أمانة ×1 │ خدمات ×1 │ مريض ×1
  (بدون تبرير، مأمورية متاحة أيضاً)
الرقيب يحفظ → قائد السرية يقرأ/يعتمد → قائد المركز يمشط أياً من التقارير
```

## 3) أعمدة الأنظمة الآمنة (Offline-Safe Trust)

1. **Hash-Chain** لكل جلسة حضور (تسلسل تام: session hash → prev_hash) — أي تعديل يكسرها فوراً
2. **QR تحقق** في PDF التقارير — تحقق محلي (بلا تكبير إداري أو وثقة إنترنت)
3. **No post-finalization edits** — التعديل بلا ازالة: بدله سجل مغَير "request_correction"
4. **UBL للاعتماد**: فقط من دور الرقيب أو الاعلوي (كتابة admin إدك سجل audit كلها)
5. **RLS + Roles** دائماً (سحابي ومحلي)

## 4) عناصر FCM (Phase 4 إن أوقف)

- إطلاق Firebase (مشروع `ausar-military`) + service account JSON في Vercel/Supabase Secrets
- Edge Function `send-fcm` + جدول `device_tokens` (RLS لكل المستخدمين)
- الحدث — الموثق: تقرير ختم (فوحا للسرية) | غياب مجهول فوري | غياب متكرر > 3 | تبرير قادم | وجزة يوم 20:00
- Topic: `inst_{id}_unit_{cohort_id}` (مسirical للأجهزة بس)
